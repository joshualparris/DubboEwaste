# Delivery roadmap and honest parity measurement

This benchmark expands the product goal. It does not change the existing app or confirm existing shipped checkboxes.

1. **Reconcile P0:** map AFB-INV/DATA control requirements to existing screens, database constraints and realistic tests. Prioritise unresolved media, identity, holds, evidence and concurrent release. An attractive certificate is insufficient.
2. **Complete daily processing:** receiving to media accounting, diagnosis, repair/parts, grade, release and confirmed downstream outcome. Add one authentic erasure-report adapter and one tested scanner/printer path before accumulating connectors.
3. **Recover value:** evidence-based listings, stock reservation, pick validation, returns, realised unit economics and agreed profit-share settlement. Add accounting and marketplace integrations individually.
4. **Client confidence:** isolated portal, private evidence, report versions, reconciliation and client-specific service rules. Add ESG only with versioned assumptions and confirmed outcomes.
5. **Enterprise/mobile extensions:** paid IMEI and management-state checks, employee recovery, device-specific automated diagnostics and independent erasure verification.
6. **Hardware automation:** assess robotics after throughput and labour measurements justify equipment. A queue or AI label is not robotic parity.

## Coverage ledger

For every AFB ID record: implementation path, database/API control, test reference, supported device/format scope, dependencies, owner and last test date. Statuses: proposed, designed, foundation, implemented, tested, externally blocked, unsupported. Only tested counts as delivered.

Coverage = tested applicable requirements / all applicable requirements. Publish exclusions alongside the number; do not shrink the denominator to make progress look better. Weight critical release/security requirements separately. Passing aggregate coverage never excuses a failed critical control.

To claim union parity: close vendor-demo gaps, create feature-level source mappings, expand requirements for newly discovered capabilities and demonstrate every applicable capability with representative success/failure cases. To claim superiority: measure processing time, error rate, evidence completeness, reuse recovery, cost and operator usability against a documented baseline. Feature count alone is insufficient.

## Build versus integrate

Build the identity, custody, operational workflow, evidence, economics, portal and reporting spine. Integrate validated erasure engines, external ITAM registries, marketplace/accounting systems and hardware bridges. Do not imply AssetFlow inherits their certifications. Optional local agents should have scoped task permissions, signed results and no general fleet-control authority.
